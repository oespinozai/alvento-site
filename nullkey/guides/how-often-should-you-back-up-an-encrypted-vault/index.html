How often should you back up an encrypted vault?

There is no fixed schedule. Back up after changes you would miss, and keep each backup's own passphrase or recovery key apart from the backup file.

Base it on how fast your vault changes

There is no single correct interval. A useful rule is to make a fresh encrypted backup after changes you would miss, such as new documents, a batch of photos or notes you depend on. A backup is a snapshot of the vault at the moment you export it, so its age is simply how long ago that moment was.

A vault you add to often needs backups more often than one you open once a year. Pick a trigger you will remember, such as finishing each import or receiving an important new letter.

Consider a trigger based on the work you do rather than the calendar, because a quiet month can still hold one important import.

What a backup can and cannot cover

A backup holds the vault as it was when you saved it. Anything added afterwards exists only on the phone until your next backup, so if the phone is lost in between, that work is gone.

Keeping more than one dated backup can help if a file turns out to be unusable. Each one still needs the passphrase or recovery key it was made with, because changing your credentials later does not update earlier backup files.

If you change credentials every so often, note the date of each change, so you can tell which backups still match the current passphrase and which need their older secrets.

A routine you can repeat

Repeat this on the trigger you picked, rather than trying to remember when you last did it.

  • Finish the changes you want to keep, such as imports or edits.
  • On your unlocked phone, open Settings and choose Create encrypted backup.
  • Pick a destination in Android's document picker.
  • Wait for the message that says the backup was saved and checked.
  • Store the file and its matching passphrase or recovery key in separate places.
  • Note the date beside the secret, so you know which backup it opens.

How NullKey handles this

Limit: each backup holds only what the vault held at that moment, and later changes to your passphrase or recovery key do not reach it. Alvento cannot recreate anything added after your last backup.

A backup still needs a test

A backup you have never opened is an assumption. From time to time, make a test restore with sample data into an empty vault on a device you do not depend on, so you know the steps and the secret work before you need them.

A rehearsal also shows roughly how long the process takes on your phone, which helps when you decide how often to schedule it. If your backups live with a cloud provider, include downloading the file in the rehearsal, because that is the step most likely to trip you up on a new phone.

Frequently asked questions

How many backups should I keep?

Keep at least your most recent backup, and older ones only if you can also keep the secret that opens each. Several dated files can help if one is damaged, but every copy you keep needs protecting too. A simple label on each file, with its date, makes that much easier.

Do I need a backup after every small change?

Not usually. Back up after changes you could not afford to lose, because anything added after the last backup exists only on the phone until the next one is made.

Does the app back up on a schedule by itself?

No. There is no automatic backup, so tie each one to an event you will notice, such as finishing an import, and keep to that routine.
